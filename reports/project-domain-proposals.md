# Ordinary-domain proposals within a project draft

## User-facing gap and minimal choice

A source-informed draft can list every parameter yet leave an owner unable to see a concrete ordinary-use proposal. Closing every question automatically would be worse: it would convert observations into authority and hide wider input policies. CAAC-014/016 require input and guarantee distinctions; CAAC-003/004/017 preserve unresolved admission and rejection meaning.

The existing candidate decision mechanism already represents the needed distinction. This exercise uses four `propose-decision` answers, not a new schema, parser, wrapper or admission checker. The questions remain required and unresolved. A pending decision proposal does not become adopted clause applicability. A separate explicit semantic revision and the applicable acceptance process would be needed before claiming that outcome.
