## Scope and choice of tool

This increment connects existing crawk output to collection, review-packet citations and actual skill-authored candidate generation. It advances the 0.10 generation flow, not the planned 0.11 execution-evidence gate. No Pigeon source, contract, service, queue or other worker's draft was changed.

An independent Ponytail review favored reusing crawk over adding narrower Tree-sitter path observations. Crawk already provides substantive dependency analysis and SCC operations. Its inspected 0.7.1 CLI and library lack exact source spans and retain bare dependency labels that can be ambiguous across targets. The library also invokes Cargo metadata. Importing retained outputs avoids pretending that a library wrapper solves those limits or authorizes arbitrary repository execution. No new source parser/resolver, dependency, graph engine or analyzer subprocess was added. A narrow retained-output grammar parser validates the selected analyzer text.

The [adapter guide](../docs/crawk-evidence.md) defines explicit selections, grammar, resource limits and authority boundaries. Source output citations remain separate from analyzer-output citations. Snapshot entries never grant permission to read files.

## Independent resource finding and repair

Code-only review found a real amplification risk: many inventory targets sharing one bare label could cause every dependency to copy thousands of match indices. Individual input and record limits did not bound allocation before final serialization.

The repair builds one bounded label index and checks a cumulative 65,536 endpoint-match-slot limit before copying either endpoint. It rejects excess input without truncating ambiguity or publishing output. The adversarial regression covers the repeated-label expansion and exact-budget retention. Independent re-review closed this blocker. The bound is a resource policy, not a sizing threshold or meaning filter.
